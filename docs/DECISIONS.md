# 決定事項

## 2026-10-29 キャンバスの原寸対応

- チャート画像は元の画素数で読み込む。6400 × 1800 px を扱えるよう、キャンバス幅の通常入力上限を8192 pxに広げる。読み込み済み画像・現在値が通常上限を超える場合も、入力確定だけで縮小しない。
- キャンバス設定に「デフォルトに戻す」を追加する。戻し先は選択中のチャート画像の原寸（たたみさん確認済み）、画像なしの場合は1920 × 1080 pxとし、ボタンに寸法を表示する。
- サイズを戻してもFixtureの座標・大きさ・Patchを変更しない。Undoでサイズ変更を取り消せる。
- Mac版とWindows版は同じ変更から作成する。ビルド成功と実機動作確認を区別して報告する。
- 公演名・実画像はリポジトリやPRへ含めない。

## 2026-10-29 LED面・方眼・図形取り込み

- 今回の指示ではLED以外を透明にし、LED面を編集用のグレーで表示する。原画像を保存ファイル内に保持し、チャートメニューから戻せる。グレーと方眼は編集用で、映像出力へ追加しない。
- 色付きの外枠と格子を持つ矩形LED面をローカルで検出する。確信できない画像は加工せず、検出失敗を表示する。任意の写真・曲面・すべての図面の認識は保証しない。
- LED面の左上を基準に既定10pxの方眼と吸着を使う。設定で1〜500pxに変更でき、密すぎる表示倍率では方眼だけ省略する。
- Vectorworks図形はテキストDXF経由で線として取り込む。元の寸法・単位を表示し、指定LED面へ縦横比を保って中央配置する。既存Patchは変更しない。円弧などは折れ線に変換する。
- 直接のVWXコピー＆ペースト、PDF正面図からの寸法・LED配置抽出、指示によるバランス配置は未実装。実際の正面図と対象電飾を受け取ってから寸法・配置規則を確認する。DXFの比率合わせを実寸の校正済みと説明しない。
- 非公開の図面・公演情報・検証スクリーンショットはリポジトリへ追加しない。

## 2026-10-31 配布フォルダの整理

- 配布フォルダの直下には現在のチャート・現在の作業データ・最新版のアプリのみを置く。
- 新しい版を追加するときは、旧版・旧配置案・補助的な確認画像や説明ファイルを、同じフォルダ内の `Old` に移す。削除せず保管する。
- 実行中アプリと現在開いているデータのパスは、整理だけを目的に移動・変更しない。

## 2026-10-31 点灯確認の見やすさ

- 卓なしで確認を開いている間は、キャンバスの選択枠・頂点・Fixture番号・方眼・寸法表示を隠す。閉じると通常の編集表示に戻す。選択とPatchは維持する。
- 認識済みLED面の編集用背景を暗いグレー（#303030）にする。既存データにも適用し、映像出力には含めない。
- 上端配置は線幅まで考慮し、最上段ピクセルの外へ線がはみ出さない位置とする。

## 2026-10-31 背景とタワー単位のPatch

- LED面の編集背景をさらに暗い #202020 に変更する。
- Patchは各側のセンター1基の外枠・丸・四角をすべて採番してから、その外側1基、サービス1基へ進む。各タワー内の順序と上手のミラー反転は維持する。

## 2026-10-31 細い線の送信

- 原寸チャート・実寸・配置・Patchは維持する。送信解像度は既存設定を使用し、いつでも変更可能。
- 線・折れ線・フリーハンドを送信上の1pxで直接描く設定を追加する。既存データは未設定=OFFで以前の表示を維持する。
- ONでは原寸画像の縮小を経ず送信ピクセルに量子化する。位置の丸めと丸・斜線の階段状の輪郭が生じる。グロー付き・繰り返し図形・その他の灯体は従来描画を維持する。
- MacのGPU出力とCPU/Windows出力で同じ処理を使う。NDI送信前のRGB検証と、受信後の画質・遅延の実測を区別する。

## 2026-10-31 MVRのUniverseとFixture ID

- チャート1・2の両方を下手Universe 21、上手Universe 22へ移す。各FixtureのDMX開始アドレス・順序・配置・形状は維持する。
- MVRのFixture IDは「チャート番号 × 100000 ＋ Universe番号 × 1000 ＋ Universe内の連番（1始まり）」とする。チャート1は121001／122001、チャート2は221001／222001から開始（たたみさん確認済み）。
- 発光形状付きGDTF、RGB 3ch＋Virtual Dimmerを維持する。旧データ・旧MVRは配布フォルダのOldへ保管する。
- チャート1・2の旧MVRはたたみさんより問題なさそうとの報告あり。今回のUniverse・ID変更版の卓上確認とは区別する。

## 2026-10-31 MVRの奥行き

- MVRは舞台前をY=0、舞台奥方向を+Yとし、LED面ごとに指定された奥行きを設定する。1間は1800mmとして換算する。
- 奥行き変更ではX・Z、発光形状、Fixture ID、Universe・DMXアドレスを変更しない。Stage Imagerの2Dチャートの上下座標とMVRの奥行きYを混同しない。
- 公演固有のLED面別奥行き値と確認結果はローカルの検証記録へ保存し、公開リポジトリへ含めない。

## 2026-10-31 次回のGDTF共通化と表示線幅

- 次回のMVR書き出し改修では、同じ長さ・同じ発光線幅・同じDMX仕様の直線を共通GDTF／FixtureTypeにまとめる。位置・向きはMVRの変換行列で表現し、向きの違いだけでFixtureTypeを増やさない。
- GDTF上の発光線幅は視認用に50mmとする。Stage Imagerの描画線幅、NDI出力の線幅、チャートの実寸・配置・Patchは変更しない。
- 同じ形状・寸法の丸も共通化対象とする。長さ・形状が異なるものを種類数削減のために勝手に変形しない。
- 次回対応として承認済み。現時点の配布MVRには未反映。共通化後は正面形状・位置、奥行き、Fixture ID、Patch、RGBとVirtual Dimmerの維持を検証する。

## 2026-11-05 DMXによるArt-Net遅延切替（実装・初期案）

- 既存のUniverse別遅延・送信先・マージ設定を維持し、全行共通で遅延だけをDMXでON/OFFする設定を追加する。OFFでも転送を続ける。
- 新しい切替機能は初期無効。古い設定の読込時も無効とし、最初の有効な制御受信前は従来の遅延を使う。制御Universe・Channelは実際のPatchを確認して設定する。
- 閾値128、制御信号のタイムアウト5500ms、信号断時は直前の状態保持を変更可能な初期案として実装する。本番の確定値ではない。信号断時は遅延OFF／ONも選べる。
- 制御値はマージ・遅延処理の前に読む。短くて制御Channelを含まないパケット・自分自身の転送パケットでは状態と信号断タイマーを更新しない。
- 遅延状態が変わる時は待機中の旧フレームを全て破棄し、次に受信したフレームから新状態で転送する。設定変更と終了時には制御信号のタイマーも破棄する。
- チャート保存形式は変更しない。ローカルの自動テスト・Macテスト版の画面確認と、DMXノードの実機確認を区別する。


## 2026-11-05 LED外枠の訂正・資料管理

- LED面そのものの外枠を描き、実際のL字の折れ角に縦線を入れて、設置された箱に見せる。床面に置かれた箱の姿勢を基準とし、LED内へ傾いたキューブ図形を複製する案は採用しない。
- 平らなLED面には架空の角の縦線を入れない。DMXの区切りと物理的な折れ角を分けて扱う。
- 既存の枠線電飾を生かす部分では、足りない辺だけを補完候補にする。既存灯体の制御・Patchを変更しない。
- 線幅はチャート上2px。線の端までLED枠内に収まる位置を使い、チャート保存形式を維持する。
- 新規2 UniverseのRGBパッチを明示して生成し、旧灯体の点灯順に対応するアドレス枠を保つ。非表示の辺の枠は無理に詰め直さない。同じ論理キーの線は共有Patchで連動する。
- 入力元・資料・元のチャートを上書きしない。公演資料・具体的な形状・配置・Patch・生成チャート・画像・確認記録はリポジトリ外で管理し、GitHubへ含めない。
- 寸法注記と実際の図形寸法に食い違いがある場合、実寸校正済みと扱わない。配置案・アプリ読込・画面の目視・実機出力を区別する。
- DMX遅延制御の信号断判定の初期案は既存受信処理と同じ5500ms。既に保存されたユーザー指定値は維持し、本番設定は未確定のままとする。
